## Scope and acceptance established before changing the renderer

Change Grain only, keeping its controls/defaults, seed/hash field, and ABI stable.
Before production edits, add an independent double-precision final-stage oracle
and run it against the unchanged v0.9.7 library. Check amount, size, chromatic
mix, animation, signed layer coordinates, row padding, transparent/tiny/partial
alpha, extended RGB, and four Glow/Diffusion combinations. A tolerance of 5e-6
is fixed for the new CPU oracle. Grain-free base output must remain unchanged.

On the current parent the final oracle fails 593,077 of 1,331,762 assertions.
After implementation it passes all. The first draft oracle incorrectly ignored
an existing size upper clamp for Size=11; the oracle was corrected to the public
0.3..5 input range / existing effective 0.5..5 behavior, then both parent and new
libraries were tested again. No test tolerance or production range was relaxed.

## Source observation vs implementation decision

Read-only inspection of the user-supplied Cosmic.aex (SHA-256
`b1b55fc6f0795dad45dfd1e79bfd180eb6d881519aade4250bd6416d737a3ea8`)
shows a channel-dependent grain envelope in the composite path:

`amount * 0.3 * (0.15 + 0.85 * clamp(straight_channel, 0, 1))`.

The existing Stellar implementation applied unweighted noise to the base before
Glow/Diffusion. This explains an amplitude mismatch without choosing an arbitrary
noise divisor. The Windows shader observation is not by itself proof of Mac
execution; the already returned Mac isolation frame supplies an independent
statistical check of this model at Amount=20%, Size=1, Color=100%, Animate=Off.

We independently implement the envelope but RETAIN Stellar's existing PRNG,
per-channel salts and seed policy. The reference random pattern/seed mapping is
not reproduced or claimed. The channel envelope is evaluated in premultiplied
form without division: `0.3 * (0.15*a + 0.85*clamp(v,0,a))`. Only the noise
amplitude is clamped; signed and extended-range RGB is NOT clamped and alpha is
not modified. This deliberately preserves Stellar's established HDR/under-range
contract rather than copying the original composite's lower RGB clamp. Original
negative-value parity and other grain sizes/frames remain unverified.

Grain is now applied once at the final output: direct base, post-Glow when there
is no Diffusion, or post-Diffusion. It is not included in glow-source/mip data.
CPU uses the existing final loops, with no added frame pass or scratch allocation.
Metal mirrors the equation and uses the three final-output kernels only; its
tracked embedded source header was regenerated byte-for-byte. No native SDK
struct, parameter ID, color preset, default value or random hash was changed.
The version and the root Cargo.lock package entry are 0.9.8; dependency entries
and checksums are unchanged.

- Baseline strict: 8/8. New core strict: 9/9.
- AddressSanitizer + UndefinedBehaviorSanitizer: 9/9, leak detection enabled.
- ThreadSanitizer: 9/9, halt-on-error enabled.
- CPU bridge parity, 8/16/32-format/HDR and concurrent-render tests: PASS.
- Ten build/package identity fixture tests: PASS.
- Static Metal placement/header checks and three negative mutation tests: PASS.
  This does not compile or execute a Metal shader.
- Existing static contracts and expanded source freeze: PASS.

The grain-free base golden stays identical. Two composite goldens intentionally
change because noise no longer feeds the blur passes. Their finite output/alpha
and visual previews were reviewed before updating values; old/new signatures
and unchanged tolerances are retained in `evidence/GRAIN_098_LOCAL.json`.
The independent oracle and reference statistics, not the updated golden, supply
the correctness evidence for this limited change.

Three alternating, nonconcurrent before/after CPU benchmark process runs included
warm-up. They are recorded without a speedup claim. Full-render medians increased
from 26.664 to 29.652 ms at 640x360 and 102.571 to 106.763 ms at 1280x720 in this
sandbox. This cost is disclosed, not hidden as a performance PASS. Corrected final
grain operates over blurred coverage; real AE profiling and optimization remain
open. These short sandbox timings cannot establish hardware-wide performance.

## Open gates and next work

Mac Rust/build/signing, actual AE 0.9.8, real Metal execution and full CPU/GPU
parity are BLOCKED/NOT RUN. No native candidate is handed off. A GitHub patch
publication followed by clean Mac CI is needed before the next host stage.

Turbulence and Softness were investigated but NOT modified. Returned Size=3/6
fixtures and the colorize path show that simply reducing Grain cannot solve
Turbulence's spatial mismatch. A frame-fitted coordinate multiplier is not an
acceptable substitute for establishing the reference noise/coordinate contract.
Depth shape/Softness, Glow/Diffusion algorithms, presets, group order, ROI rounding,
loaded identity, lifecycle/migration and host profiling remain open. The user
already supplied useful evidence; no repeated diagnostic run is requested here.

Old projects retain values and IDs but render changed Grain. Backward visual
identity is not promised; reverting this source commit restores 0.9.7 behavior.
Do not label old 0.9.6 host tests as evidence for 0.9.8.
